2. 메모리 사용량 비교

실험 결과 희소 그래프에서는 Kruskal 알고리즘을 사용한 인접 리스트의 메모리 사용량이 5808 Bytes로 가장 적었다. 반면 Prim 알고리즘을 사용한 인접 행렬은 11208 Bytes를 사용했다. 인접 리스트는 실제로 연결된 간선 정보를 저장하기 때문에 간선 수가 적은 희소 그래프에서 메모리를 적게 사용하는 것을 확인할 수 있었다.

밀집 그래프에서는 Kruskal의 인접 리스트가 27808 Bytes를 사용했다. 희소 그래프보다 간선이 6배 많아지면서 저장해야 하는 간선 정보도 많아졌기 때문이다. 반면 인접 행렬은 정점 수가 동일하기 때문에 희소 그래프와 밀집 그래프 모두 11208 Bytes로 동일하게 나왔다.

이 결과를 보면 인접 리스트는 간선이 적은 그래프에서 유리하고 인접 행렬은 그래프의 간선 수가 달라져도 사용하는 공간이 일정하다는 특징이 있다.

3. Kruskal과 Prim 알고리즘 비교

Kruskal 알고리즘은 모든 간선을 가중치가 작은 순서대로 정렬한 다음 사이클이 생기지 않는 간선을 선택하는 방식이다. 이번 프로그램에서는 Union-Find를 사용해 사이클 발생 여부를 확인했다. 간선 정보를 정렬해야 하므로 간선 수가 많아지면 정렬에 필요한 작업도 증가한다.

Prim 알고리즘은 시작 정점을 정한 뒤 현재 트리에 연결할 수 있는 간선 중 가장 작은 가중치를 가진 간선을 선택하는 방식이다. 이번 프로그램에서는 인접 행렬을 이용해 연결된 정점의 비용을 확인하고 다음 정점을 선택했다. 인접 행렬의 크기는 정점 수에 따라 정해지기 때문에 간선이 많아져도 그래프 저장 공간은 변하지 않았다.

두 알고리즘은 MST를 만들어 가는 방식은 다르지만 같은 그래프에서 구한 전체 비용은 동일했다. 희소 그래프에서는 둘 다 14798이 나왔고 밀집 그래프에서는 둘 다 2282가 나왔다. 선택한 간선의 순서와 구성은 달랐지만 최종적으로 최소 비용 신장 트리를 구했다는 점에서 결과가 일치했다.

4. 그래프 밀도에 따른 차이

희소 그래프는 간선이 100개이고 밀집 그래프는 600개이기 때문에 밀집 그래프에서 저장해야 하는 간선 정보가 더 많았다. 실제로 인접 리스트를 사용한 Kruskal의 메모리 사용량도 희소 그래프의 5808 Bytes에서 밀집 그래프의 27808 Bytes로 증가했다.

반면 인접 행렬은 정점 50개를 기준으로 항상 같은 크기의 배열을 사용하기 때문에 두 그래프의 메모리 사용량이 동일했다. 따라서 그래프의 간선이 적을 때는 인접 리스트가 공간을 절약하는 데 유리하고 간선이 많을 때는 인접 행렬을 이용해 간선 정보를 바로 확인할 수 있다는 장점이 있다.

알고리즘의 실행시간은 그래프의 밀도뿐 아니라 간선 정렬 여부와 정점 탐색 방식에도 영향을 받는다. Kruskal은 간선을 정렬하는 작업이 필요하고 Prim은 인접 행렬에서 최소 비용을 가진 정점을 찾기 위해 정점들을 반복해서 확인한다.

5. 실행시간 결과 및 느낀 점

이번 실행에서는 네 가지 경우의 실행시간이 모두 0.000000 ms로 출력되었다. 그래프의 크기가 비교적 작아서 한 번의 실행시간이 너무 짧았기 때문이라고 생각한다. 따라서 이번 결과만으로 어떤 알고리즘이 더 빠르다고 확실하게 판단하기는 어렵다. 실행시간을 제대로 비교하려면 알고리즘을 여러 번 반복해서 실행하고 평균 시간을 구하는 방법이 필요하다.

이번 과제를 통해 그래프를 어떤 방식으로 표현하는지에 따라 메모리 사용량이 달라지고, MST를 구하는 알고리즘에 따라서도 필요한 자료구조와 작업 과정이 달라진다는 것을 알 수 있었다. 특히 간선이 적은 그래프에서는 인접 리스트가 메모리 면에서 유리했고, 인접 행렬은 간선 수와 관계없이 일정한 공간을 사용한다는 점이 인상적이었다.
