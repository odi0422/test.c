1. 데이터 크기에 따른 비교 횟수 변화

데이터 크기가 커질수록 세 가지 퀵 정렬 방법 모두 비교 횟수가 증가하는 것을 확인할 수 있었다.

1000개일 때는 First가 11178회 Random이 10701회 Median-of-Three가 11121회였고 20000개일 때는 각각 318954회 349456회 319189회로 증가하였다.

전체적으로 데이터 크기가 증가하면서 비교 횟수도 증가했지만 데이터 크기에 정확히 비례해서 증가하지는 않았다. 피벗을 선택하는 방식에 따라 분할 결과가 달라지기 때문이다.

2. 피벗 선택 방법에 따른 성능 차이

First 방식은 현재 구간의 첫 번째 원소를 피벗으로 사용한다. 구현이 간단하다는 장점이 있지만 피벗이 한쪽으로 치우친 값이면 분할이 불균형하게 이루어질 수 있다.

Random 방식은 매번 무작위 위치의 원소를 피벗으로 선택하기 때문에 특정 데이터 순서에 영향을 덜 받는다는 장점이 있다. 하지만 무작위로 선택하기 때문에 실행할 때마다 비교 횟수가 달라질 수 있고 이번 실험에서도 20000개 데이터에서는 349456회로 가장 많은 비교가 발생했다.

Median-of-Three 방식은 첫 번째 원소와 가운데 원소 마지막 원소 중 중앙값을 피벗으로 선택한다. 세 값 중 가운데에 해당하는 값을 사용하기 때문에 한쪽으로 치우친 분할을 줄이는 데 도움이 된다.

실험 결과 4000개부터 16000개까지는 Median-of-Three 방식이 가장 적은 비교 횟수를 기록했다. 특히 16000개에서는 246727회로 세 가지 방법 중 가장 적은 비교가 발생했다.

3. 피벗 선택이 성능에 영향을 미치는 이유

퀵 정렬은 피벗을 기준으로 작은 값과 큰 값을 나누는 과정을 반복하는 정렬 방법이다. 이때 피벗이 데이터의 중앙에 가까운 값이면 두 구간이 비슷한 크기로 나누어져 정렬 과정이 효율적으로 진행된다.

반대로 피벗이 가장 작은 값이나 가장 큰 값에 가까우면 한쪽 구간에 데이터가 몰리게 되고 분할 과정이 반복되면서 비교 횟수가 증가할 수 있다.

따라서 피벗을 어떤 방식으로 선택하는지가 퀵 정렬의 전체적인 성능에 큰 영향을 준다는 것을 알 수 있었다.

4. 보너스 - 재귀적 퀵 정렬과 반복적 퀵 정렬 비교

데이터 크기 10000개와 Median-of-Three 피벗 선택 방식을 동일하게 사용하여 재귀적 방법과 반복적 방법의 실행시간을 비교하였다.

재귀적 퀵 정렬은 평균 2.0001ms가 측정되었고 반복적 퀵 정렬은 평균 1.6000ms가 측정되었다.

이번 실험에서는 반복적 퀵 정렬이 재귀적 퀵 정렬보다 약간 더 빠른 결과를 보여주었다.

재귀적 방법은 분할할 때마다 함수를 호출하고 이전 실행 상태를 스택에 저장해야 한다. 반면 반복적 방법은 직접 스택을 사용하여 정렬할 구간을 관리하기 때문에 함수 호출에 필요한 추가적인 작업을 줄일 수 있다.

다만 실행시간은 컴퓨터 환경이나 실행 당시의 상태에 따라서 달라질 수 있으므로 항상 반복적 방법이 더 빠르다고 단정할 수는 없다.

5. 최종 분석

이번 실험을 통해 퀵 정렬은 같은 데이터와 정렬 방법을 사용하더라도 피벗을 선택하는 방식에 따라 비교 횟수가 달라진다는 것을 확인할 수 있었다.

전체적인 결과를 보면 Median-of-Three 방식이 비교적 안정적으로 적은 비교 횟수를 보여주었으며 특히 데이터가 많아질수록 효과적인 모습을 보였다.

Random 방식은 데이터에 따라 결과 차이가 있었고 First 방식도 데이터의 구성에 따라 비교 횟수가 달라질 수 있었다.

따라서 이번 실험에서는 Median-of-Three 방식이 가장 효과적인 피벗 선택 방법이라고 생각한다. 또한 재귀적 방법과 반복적 방법의 실행시간도 차이가 발생한다는 것을 확인할 수 있었다.
