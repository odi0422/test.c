# 퀵 정렬과 AVL 트리 정렬 성능 비교

이번 과제에서는 동일한 무작위 정수 데이터를 사용하여 퀵 정렬과 AVL 트리 정렬의 성능을 비교하였다. 데이터 크기는 1,000부터 20,000까지 증가시키면서 실험하였으며, 정렬이 끝난 후 최초 데이터 크기의 20%만큼 삽입과 삭제 연산을 수행하였다.

퀵 정렬은 Median-of-Three 방식으로 피벗을 선택하였고, AVL 트리는 데이터를 삽입할 때마다 균형을 유지하도록 구현하였다.

## 1. 총 수행시간 및 비교 횟수

실험 결과 데이터 크기가 증가할수록 두 방법의 수행시간과 비교 횟수 모두 증가하였다.

퀵 정렬은 데이터가 2,000개일 때 4.009ms였지만 20,000개에서는 427.991ms까지 증가하였다. 반면 AVL 트리는 2,000개에서 3.977ms, 20,000개에서 16.001ms로 측정되었다.

비교 횟수에서도 큰 차이가 나타났다. 20,000개 데이터 기준으로 퀵 정렬은 62,740,099회, AVL 트리는 473,958회로 측정되었다.

퀵 정렬은 처음 정렬할 때는 효율적이지만 정렬 이후 배열에 삽입하거나 삭제할 때 기존 데이터들을 탐색하고 이동시키는 과정이 필요하다. 반면 AVL 트리는 균형을 유지하면서 삽입과 삭제를 진행하기 때문에 비교 횟수가 상대적으로 적게 나타난 것으로 생각된다.

## 2. 데이터 이동 횟수

데이터 이동 횟수는 퀵 정렬이 AVL 트리보다 훨씬 많았다.

20,000개 데이터 기준으로 퀵 정렬은 25,247,446회, AVL 트리는 22,036회로 측정되었다.

배열은 삽입할 위치를 찾은 다음 기존 데이터들을 뒤로 이동시켜야 하고, 삭제할 때도 빈 공간을 채우기 위해 뒤에 있는 데이터들을 앞으로 이동시켜야 한다. 데이터가 많아질수록 이러한 작업이 반복되면서 이동 횟수가 크게 증가한다.

반면 AVL 트리는 노드의 연결 관계를 변경하는 방식으로 삽입과 삭제를 수행한다. 포인터 변경은 데이터 이동 횟수에 포함하지 않기 때문에 AVL 트리의 이동 횟수가 훨씬 적게 나타났다.

## 3. 메모리 사용량

메모리 사용량은 퀵 정렬이 AVL 트리보다 적게 나타났다.

20,000개 데이터 기준으로 퀵 정렬은 96,736바이트, AVL 트리는 622,656바이트를 사용하였다.

배열은 데이터를 연속된 메모리 공간에 저장하기 때문에 별도의 노드 정보가 필요하지 않다. 반면 AVL 트리는 각 노드마다 데이터뿐만 아니라 왼쪽과 오른쪽 자식 노드의 주소, 높이, 중복 횟수 등을 저장해야 한다.

이러한 구조적인 차이 때문에 AVL 트리는 삽입과 삭제에서는 효율적이지만 메모리 사용량에서는 배열보다 불리한 모습을 보였다.

## 4. 데이터 크기 증가에 따른 성능 변화

데이터 크기가 증가할수록 퀵 정렬의 수행시간과 비교 횟수, 데이터 이동 횟수가 크게 증가하였다.

특히 퀵 정렬의 수행시간은 4,000개에서 15.998ms였지만 20,000개에서는 427.991ms까지 증가하였다. AVL 트리는 같은 조건에서 4.001ms에서 16.001ms로 증가하였다.

이러한 차이는 삽입과 삭제 방식에서 발생한다고 생각한다. 배열은 데이터가 많아질수록 삽입과 삭제 과정에서 이동해야 하는 데이터도 많아진다. 반면 AVL 트리는 균형을 유지하면서 필요한 부분만 수정하기 때문에 데이터가 증가해도 비교적 안정적인 성능을 보여주었다.

## 5. 종합 분석 및 결론

이번 실험을 통해 퀵 정렬과 AVL 트리는 각각 다른 장점을 가지고 있다는 것을 알 수 있었다.

퀵 정렬은 배열을 사용하기 때문에 메모리 사용량이 적고 일반적인 정렬 작업에 적합하다. 하지만 정렬 이후 삽입과 삭제가 반복되면 기존 데이터를 이동시켜야 하기 때문에 데이터 이동 횟수와 수행시간이 크게 증가하였다.

반면 AVL 트리는 배열보다 메모리를 많이 사용하지만 삽입과 삭제 과정에서 전체 데이터를 이동시킬 필요가 없고, 회전을 통해 균형을 유지하기 때문에 반복적인 데이터 변경에 유리하였다.

따라서 데이터를 한 번 정렬하고 이후 변경이 거의 없는 상황에서는 퀵 정렬이 적합하고, 정렬된 상태에서 삽입과 삭제가 자주 발생하는 상황에서는 AVL 트리가 더 적합하다고 생각한다.

마지막으로 모든 데이터 크기에서 두 방법의 최종 데이터 개수가 동일하게 나왔으며, 오름차순 정렬 여부와 데이터 검증에서도 모두 PASS가 출력되었다. 이를 통해 동일한 삽입 및 삭제 연산이 두 자료구조에 정상적으로 적용되었음을 확인하였다.
