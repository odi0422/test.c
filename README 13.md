1. 데이터 크기에 따른 비교 횟수 변화

데이터 크기가 커질수록 병합 정렬과 퀵 정렬 모두 비교 횟수가 증가하는 것을 확인할 수 있었다.

병합 정렬은 데이터가 1000개일 때 8709회 비교가 발생했고 20000개일 때는 260966회로 증가하였다.

퀵 정렬은 피벗 선택 방법에 따라 차이가 있었으며 20000개 기준으로 First는 334566회 Random은 353651회 Median-of-Three는 322727회의 비교가 발생하였다.

전체적으로 병합 정렬이 퀵 정렬보다 적은 비교 횟수를 기록했다. 병합 정렬은 데이터를 항상 비슷한 크기의 두 부분으로 나누기 때문에 비교 횟수가 비교적 일정하게 증가하지만 퀵 정렬은 피벗을 어떻게 선택하느냐에 따라 분할 결과가 달라지기 때문이라고 생각한다.

2. 실행시간 비교

실행시간은 데이터 크기가 작을 때 대부분 0.0000ms로 출력되었기 때문에 정확한 차이를 확인하기 어려웠다.

16000개에서는 병합 정렬이 4.0000ms First 퀵 정렬이 4.0250ms Median-of-Three 퀵 정렬이 3.8760ms로 측정되었다.

20000개에서는 병합 정렬과 First 퀵 정렬 Random 퀵 정렬이 각각 약 4ms로 측정되었다.

실행시간은 비교 횟수와 반드시 비례하지는 않았다. 정렬 과정에서 데이터를 이동하는 방식이나 메모리 접근 그리고 함수 호출 등의 영향도 받기 때문이다.

또한 이번 측정에서는 실행시간이 매우 짧아 0.0000ms로 표시되는 경우가 있었기 때문에 정확한 성능 차이를 판단하기에는 한계가 있었다.

3. 메모리 사용량 비교

메모리 사용량에서는 병합 정렬과 퀵 정렬의 차이가 크게 나타났다.

병합 정렬은 데이터를 합치는 과정에서 원본 배열과 같은 크기의 임시 배열을 추가로 사용한다. 데이터가 1000개일 때 4132Bytes였고 20000개일 때는 80192Bytes까지 증가하였다.

반면 퀵 정렬은 별도의 임시 배열을 만들지 않고 재귀 호출을 위한 스택 메모리만 사용하기 때문에 상대적으로 적은 메모리를 사용했다.

20000개 기준으로 First는 80Bytes Random은 80Bytes Median-of-Three는 88Bytes가 측정되었다.

이러한 차이는 병합 정렬은 데이터를 합치는 과정에서 추가 배열이 필요하지만 퀵 정렬은 기존 배열 안에서 데이터의 위치를 바꾸면서 정렬하기 때문에 발생한 것으로 볼 수 있다.

4. 퀵 정렬의 피벗 선택 방법에 따른 차이

퀵 정렬은 피벗을 선택하는 방법에 따라서 비교 횟수가 달라지는 것을 확인할 수 있었다.

First 방식은 첫 번째 원소를 피벗으로 사용하고 Random 방식은 무작위 위치의 원소를 사용한다. Median-of-Three 방식은 첫 번째 가운데 마지막 원소 중 중앙값을 피벗으로 사용한다.

실험 결과 16000개에서는 Median-of-Three가 255250회로 가장 적은 비교 횟수를 기록했고 20000개에서도 322727회로 가장 적은 비교 횟수를 기록했다.

반면 Random 방식은 20000개에서 353651회로 가장 많은 비교가 발생했다.

이를 통해 무작위로 피벗을 선택한다고 항상 좋은 결과가 나오는 것은 아니며 세 원소의 중앙값을 사용하는 방식이 이번 실험에서는 비교적 효과적이었다는 것을 알 수 있었다.

5. 시간 복잡도와 공간 복잡도 비교

병합 정렬은 데이터를 계속 절반으로 나누고 다시 합치는 방식으로 작동한다. 데이터 크기와 관계없이 분할 과정이 일정하게 진행되기 때문에 최선 평균 최악의 경우 모두 O(n log n)의 시간 복잡도를 가진다.

공간 복잡도는 병합 과정에서 임시 배열이 필요하기 때문에 O(n)이다.

퀵 정렬은 피벗을 기준으로 데이터를 나누면서 정렬하는 방식이다. 평균적으로 O(n log n)의 시간 복잡도를 가지지만 피벗이 한쪽으로 치우쳐 분할되면 최악의 경우 O(n²)까지 증가할 수 있다.

공간 복잡도는 재귀 호출 스택에 따라 달라지며 평균적으로 O(log n)이지만 최악의 경우 O(n)이 될 수 있다.

따라서 병합 정렬은 일정한 성능을 기대할 수 있다는 장점이 있고 퀵 정렬은 추가 메모리를 적게 사용한다는 장점이 있다.

6. 메모리 사용량 측정 방법

메모리 사용량은 정렬 과정에서 추가로 필요한 메모리를 기준으로 계산하였다.

병합 정렬은 임시 배열의 크기와 재귀 호출 스택의 최대 깊이를 계산하여 합산하였다.

퀵 정렬은 재귀 호출 과정에서 사용하는 스택의 최대 깊이를 기준으로 계산하였다.

이때 원본 데이터 배열과 정렬 결과를 저장하기 위한 공통 배열은 제외하였다.

따라서 실제 프로그램 전체의 메모리 사용량이 아니라 각 정렬 알고리즘이 추가로 사용하는 메모리를 비교한 값이다. 또한 재귀 스택은 실제 컴파일러가 사용하는 전체 스택 프레임이 아닌 구간 정보를 저장하는 구조체 크기를 기준으로 추정하였다.

7. 최종 분석

이번 실험을 통해 병합 정렬과 퀵 정렬은 각각 다른 장단점을 가지고 있다는 것을 알 수 있었다.

비교 횟수에서는 병합 정렬이 전체적으로 더 적은 결과를 보여주었고 데이터 크기가 증가해도 비교적 일정한 증가 모습을 보였다.

반면 퀵 정렬은 피벗 선택 방법에 따라 비교 횟수에 차이가 있었지만 추가 메모리 사용량이 병합 정렬보다 훨씬 적었다.

실행시간은 측정값이 0으로 나오는 경우가 있어서 정확한 우열을 판단하기 어려웠지만 큰 데이터에서는 두 알고리즘 모두 비슷한 실행시간을 보여주었다.

결론적으로 병합 정렬은 일정한 시간 복잡도와 비교적 안정적인 정렬 성능이 장점이고 퀵 정렬은 추가 메모리를 적게 사용한다는 장점이 있다고 생각한다. 상황에 따라 적절한 정렬 알고리즘을 선택하는 것이 중요하다는 것을 알 수 있었다.
